Student Operations Automation

Routing academic updates through a private destination while retaining review, privacy, and failure visibility.

Private prototype
Role
Workflow designer and reviewer
Tools
OpenClaw, Python, JavaScript, Discord
Scope
3 workspaces / 12 scheduled tasks
Evidence

01 / Problem and constraint

Fewer places to check, without exposing classroom data.

Reviewing announcements across multiple Google Classroom subjects was cumbersome. I wanted one designated Discord destination for relevant updates, reminders, and personal study outputs.

The public explanation could not include class content, account identifiers, participants, or private server data.

02 / Decisions and implementation

Separate workspaces, reusable instructions, and purpose-based routing.

I configured three separate OpenClaw workspaces, wrote reusable instructions, set up 12 scheduled tasks, and routed selected updates to Discord.

I used AI assistance for parts of the Python and JavaScript integration, then reviewed the resulting behavior and records.

Personal data-quality workflow

Task Archive Safety Review

A human-in-the-loop process for reviewing a large personal archive without allowing status messages to substitute for verification.

Read-only review
Role
Requirements and review
Focus
Data validation and recovery
Scale
More than 10,000 task records
Control
Backup and approval required

01 / Problem and risk

Manual review was impractical; unsupervised reorganization was unsafe.

The archive had grown too large to review casually, but allowing an agent to reorganize it without safeguards risked irreversible loss of history and context.

The system needed to make uncertainty visible and preserve a recoverable path before any edit was considered.

02 / Safety process

  1. 01
    Define boundaries.

    Identify protected fields, acceptable matches, and success criteria.

  2. 02
    Analyze without mutation.

    Produce candidates and reports before changing source data.

  3. 03
    Verify claims.

    Compare the reported result with the actual destination state.

  4. 04
    Build a recoverable copy.

    Require a backup before any irreversible operation.

  5. 05
    Validate structure.

    Confirm row totals and identifier integrity across more than 10,000 records.

  6. 06
    Gate destructive actions.

    Keep merge, archive, completion, and deletion behind human approval.

Assistance & verification

The agent assisted with review, but its status message was not accepted as proof.

AI assisted

An agent assisted with reviewing the large archive and reporting its result.

I decided

I defined the protected fields, acceptable matches, backup requirement, and human approval gates for destructive actions.

I verified

I compared the reported completion with the actual result and checked row totals and identifier integrity in a recoverable copy.

Available evidence

This public note provides the aggregate scale and a reconstruction of the review process. Personal task content is not published.

03 / Result and lesson

10,000+

records in a structurally checked copy

The review caught a mismatch between an agent’s completion message and the actual result. The lesson was direct: reported completion still requires source-level verification.

What this demonstrates

Requirements, discrepancy review, backup planning, and approval controls.

Public explanations use aggregate counts and fictional examples rather than personal task content.
