Problem

Google Classroom made it cumbersome to review announcements across multiple subjects. I wanted one central Discord destination for relevant updates, reminders, and personal study notes.

My contribution

I configured and extended an OpenClaw deployment using separate agent workspaces, reusable instructions and skills, cron scheduling, Discord routing, and AI-assisted Python and JavaScript integrations.

Evidence and interpretation

  • Historical logs contain 3,254 successful, 2,420 skipped, and 220 failed scheduler records.
  • These figures measure scheduled executions—not unique announcements, meetings, or delivered messages.
  • The practical benefit was reducing repeated navigation across individual Classroom subjects; time saved was not measured.

Privacy and consent boundary

The caption component used Google Meet's built-in captions during meetings I attended and was created for personal note-taking. Participants were not asked to approve automated capture, so no real transcript, class content, participant information, server data, or configuration is published. Every public example will use fictional inputs, and the workflow should not be redeployed for shared content without organizational permission and informed participants.

Limitations and next iteration

  • No complete automated test suite or CI pipeline was present in the recovered prototype.
  • The caption-processing component was a short pilot, while other scheduled workflows ran longer.
  • A public-safe rebuild should use synthetic fixtures, least-privilege access, retries, deduplication tests, and explicit retention controls.

Human-in-the-loop AI · Data quality · Approval gates

Safely Auditing 10,700 Task Records

Personal data-quality workflow · Synthetic public presentation

Approved

Problem

Reviewing a large personal task archive manually was impractical, but allowing an agent to reorganize it without safeguards risked irreversible loss of history and context.

My responsibility

I defined duplicate criteria, preferred false negatives over aggressive merging, prohibited destructive changes without approval, challenged an incorrect completion claim, and required a validated backup.

Safety process

  1. Define boundaries. Identify protected fields, acceptable matches, and success criteria.
  2. Analyze without mutation. Produce candidates and reports before changing source data.
  3. Verify claims. Compare the reported result with the actual destination state.
  4. Build a recoverable copy. Require a backup before any irreversible operation.
  5. Validate structure. Confirm 10,700 parsed rows and identifier integrity.
  6. Gate destructive actions. Keep merge, archive, completion, and deletion behind human approval.

Result and lesson

Produced a structurally validated dataset covering 10,700 task records before considering a destructive operation.

An agent's completion message is not evidence that the intended outcome occurred.

Skills demonstrated

Human-in-the-loop automation, structured requirements, data-quality validation, failure detection, backup-first planning, and approval controls. Public examples use fictional tasks and a small synthetic dataset; no real titles, notes, schedules, URLs, IDs, or account data are included.
